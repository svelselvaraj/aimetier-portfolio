Engineering decisions

Operating an agent platform

Six decisions behind the walkthrough, and the implementation evidence for each.

Architecture

Keep the portal responsive while agents work

Hyperclip and the operator console share one API. Background workers dispatch tasks to agent runners. A thread carries the conversation, while PostgreSQL and pgvector support scoped recall across runs.

Follow the data

A request enters through the portal. A worker assigns the task, the runner invokes its adapter, and run events carry progress back to the interface. The operator can inspect the result from the same thread.

Security

Give every action a workspace boundary

The portal requires a resolved company before it opens workspace routes. Role permissions govern privileged operations. Database row-level security adds a second boundary around company data.

Inspect the boundary

Cross-company isolation tests exercise the database policies. When the portal cannot resolve permissions, it restricts access. Client telemetry records route categories and timings and omits message text and filenames.

Evaluation

Catch a regression in one agent role

A higher overall score can hide a weaker reviewer. The offline evaluation suite compares protected groups of cases against their own baselines, grouped by agent role and work category.

Inspect the release check

CI exercises a clean baseline, a seeded regression, and missing baseline coverage. A regression in a protected group or missing evidence for that group fails the check. Separate behavior cases cover approvals and task conflicts.

Observability

Measure the wait a user experiences

The chat dashboard tracks the 95th-percentile time to first visible progress alongside cold-start duration and warm-runner misses. Those signals help an operator locate the delay before changing capacity.

Walk through triage

For a slow first response, the runbook starts with the sample count and alert window. It then compares time spent starting a runner with warm-runner miss reasons and gives operators a rollback path.

Cloud portability

Put cloud-specific choices behind contracts

AWS hosts the documented portal deployment. Azure and Google Cloud infrastructure definitions expose common outputs for PostgreSQL, object storage, identity and registry configuration.

Inspect deployment scope

The storage interface has implementations for Amazon S3 and Azure Blob Storage. Terraform validation checks the Azure and Google Cloud configurations. A successful infrastructure validation establishes configuration coverage only.

Adapter portability

Change the runner and keep the workflow

A registry dispatches execution to adapters such as Claude Code, Codex and Gemini. Task ownership, approval checkpoints and the review record stay in the control plane.

Inspect the division of work

The adapter handles its runtime’s invocation and translates its results into the shared execution format. The platform can then associate usage and cost with the run and apply the agent’s configured budget.
